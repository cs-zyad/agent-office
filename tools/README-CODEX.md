# ربط تطبيق Codex بالمقر

الربط الحالي مراقبة تجريبية (قراءة فقط). تكتب الرسائل في تطبيق Codex على الماك، وتشاهد القسم النشط وحالة عمله في موقع المقر. لا تنفذ الواجهة أوامر على جهازك ولا تنشئ ثمانية أيجنتات حقيقية.

## أول مرة على الماك

افتح Terminal وشغّل هذه الأوامر:

~~~bash
git clone https://github.com/cs-zyad/agent-office.git
cd agent-office
export CODEX_OFFICE_URL="https://agent-office-git-main-cszyad.vercel.app"
read -s CODEX_OFFICE_TOKEN; export CODEX_OFFICE_TOKEN; echo
python3 tools/codex-office-bridge.py
~~~

عند أمر read -s، ألصق رمز الربط السري الذي تتسلمه من إعداد الموقع واضغط Enter. لن يظهر الرمز في الطرفية أثناء اللصق.

إذا كان المشروع موجودًا مسبقًا بدل git clone استخدم git pull. يمكن اختيار اسم المشروع بإضافة:

~~~bash
export CODEX_OFFICE_PROJECT="تطبيق الحجوزات"
~~~

افتح Codex على الماك وأرسل مهمة جديدة. بعد ذلك افتح المقر من الآيفون، وتحت عنوان مراقبة Codex أدخل نفس رمز الربط. أثناء نشاط Codex سترى حالة الغرفة المختصة. لإيقاف المراقبة اضغط Ctrl+C في Terminal.

## الخصوصية والحدود

- يقرأ الجسر ملفات ~/.codex/sessions على جهازك فقط ولا يغيرها.
- لا يرسل نص الرسائل أو الكود أو محتوى الأوامر أو مسارات الملفات إلى الموقع. يتم تصنيف المهمة محليًا باستخدام الكلمات المفتاحية ثم إرسال الحالة العامة فقط.
- الوصول إلى API محمي برمز سري محفوظ في متغيرات بيئة Vercel وليس في المستودع.
- تحفظ الحالات في Vercel Blob خاص؛ استخدام الخدمة قد يدخل ضمن فاتورة Vercel.
- قد تتأخر تحديثات الواجهة إلى نحو دقيقة بسبب تخزين Blob المؤقت.
- يعتمد الجسر على صيغة جلسات Codex المحلية؛ هذه ليست واجهة رسمية ثابتة، وقد تحتاج تحديثات Codex المستقبلية إلى تعديل الجسر.
- يجب أن يعمل الماك والجسر حتى تتم المراقبة. إذا كان الماك مغلقًا لن تُرسل أحداث جديدة.
- التخصص المعروض تقديري ولا يعني وجود أيجنت مستقل. لتشغيل عدة أيجنتات وتوزيع المهام عن بُعد، نحتاج تكاملًا منفصلًا مع Codex SDK أو app-server.

## استكشاف الأخطاء

إذا ظهرت رسالة 401، تأكد من تطابق رمز الربط على الماك والمتصفح. إذا ظهرت 503 تأكد من اتصال Vercel Blob. إذا لم تظهر حالات، افتح Codex وأنشئ رسالة جديدة وتأكد من وجود ملفات جلسات داخل ~/.codex/sessions.
